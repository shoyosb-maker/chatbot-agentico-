1. RESUMEN EJECUTIVO
=====================================================================
MotoBot es una landing comercial de un taller de motos con tres piezas:

  a) Un sitio público (index.html) que presenta servicios, catálogo
     destacado, preguntas frecuentes y un asistente flotante.
  b) Un catálogo/cotizador (catalogo.html) con precios en COP y envío de
     la cotización por WhatsApp.
  c) Un asistente conversacional con IA (chat.html) que responde con base
     en un manual técnico cargado (RAG local), complementa con búsqueda
     web solo cuando hace falta, cotiza con el catálogo oficial y analiza
     fotos de la moto.
  d) Un panel de super usuario (admin.html) que configura proveedor,
     modelo, API key, temperatura, modo de respuesta y el documento
     técnico.

Estado: el producto funciona de punta a punta en el navegador. Todavía
NO hay backend: la configuración, las claves y el documento viven en
localStorage del navegador del administrador. Ese es el límite principal
actual (ver secciones 8 y 9).

Stack: HTML + CSS + JavaScript vanilla. Sin frameworks, sin build, sin
dependencias, sin package.json. Todo se sirve como archivos estáticos.

3. ARQUITECTURA Y FLUJOS
=====================================================================
3.1 Tipos de despliegue previstos
    - Estático en el mismo origen (los 6 archivos juntos). El widget del
      landing funciona porque chat.html es del mismo origen y comparte
      localStorage con admin.html.

3.2 Flujo de configuración (super usuario)
    admin.html -> login local (usuario "admin", clave "123", validados en
    el propio HTML) -> guarda en localStorage -> chat.html lee esa misma
    configuración al cargar (loadSettings()).

3.3 Flujo de conversación en modo "híbrido" (por defecto)
    1. El usuario escribe (o adjunta foto) en chat.html.
    2. buildQuote(question) calcula una cotización determinística si el
       texto expresa intención de precio (PRICE_INTENT).
    3. webDigest(question) busca en internet:
         - OpenAI: POST /responses con la herramienta hospedada
           web_search (si falla con 400/404/422 reintenta con
           web_search_preview).
         - DeepSeek: POST /v1/tools/search (count 6).
         - Respaldo público sin clave: Wikipedia (es) + DuckDuckGo
           Instant Answer.
       Si la consulta trae imagen, NO se busca en internet.
    4. buildSystemContent() arma el prompt: reglas + los 6 fragmentos
       del manual más relevantes (TF-IDF) + catálogo completo + la
       cotización calculada + (si aplica) los datos de internet.
    5. Se envía a /chat/completions con stream:true y se pinta la
       respuesta en vivo (SSE).
    6. stripLinks() elimina URLs, dominios y enlaces del texto.
    7. Si la consulta es de repuestos/servicios/compra (o hay cotización
       o foto), appendContact() añade el cierre con enlace de WhatsApp
       precargado. El modelo tiene prohibido escribir ese cierre.

3.4 Flujo en modo "solo manual" (doc)
    Igual, pero sin búsqueda web, con 4 fragmentos de contexto y el
    SYSTEM_PROMPT estricto ("si no está en el documento, dilo").

3.5 Flujo de imagen
    El botón "+" abre menú Fotos / Cámara. La imagen se reduce a 1280 px
    y se comprime a JPEG 0.82 (downscaleImage) y se envía como
    image_url en el mensaje. Solo disponible con OpenAI (vision:true).
    Con DeepSeek activo se avisa por toast y no se permite adjuntar.

3.6 Flujo de imagen entrante desde el catálogo
    chat.html acepta ?q=texto: precarga el input y envía automáticamente
    a los 250 ms. (El parámetro está implementado pero HOY NINGUNA
    página lo usa -> ver pendiente F-01.)

5. ALMACENAMIENTO (localStorage / sessionStorage)
=====================================================================
  motobot_provider        'deepseek' (por defecto) | 'openai'
  motobot_temp            temperatura (string numérico)
  motobot_mode            'hybrid' | 'doc'
  motobot_doc             texto completo del manual cargado
  motobot_key_openai      API key de OpenAI
  motobot_model_openai    modelo elegido para OpenAI
  motobot_key_deepseek    API key de DeepSeek; si no hay ninguna guardada
                          se usa la key de pruebas de config.js
                          (PROVIDERS.deepseek.defaultKey)
  motobot_model_deepseek  modelo elegido para DeepSeek
  motobot_admin           (sessionStorage) marca de sesión del panel

  Valores por defecto (navegador limpio):
  - DeepSeek siempre tiene key: la guardada o la de pruebas.
  - motobot_doc: si la clave NO existe en localStorage se descarga
    documento_motos.txt por fetch y se guarda. Si existe (aunque esté
    vacía porque se pulsó "Vaciar documento") se respeta tal cual.
  - motobot_provider: 'deepseek' por defecto (solo pasa a 'openai' si el
    panel lo guarda así).
  - Capacidad de imagen: config.js declara visionModels por proveedor y
    modelSeesImages(provider, model) decide; el chat, el panel y el aviso
    del modelo usan esa misma función.

  Consecuencia: la configuración es POR NAVEGADOR. Un navegador nuevo ya
  arranca con DeepSeek activo (key de pruebas + deepseek-flash), con el
  documento_motos.txt cargado y con las fotos habilitadas: el chat
  funciona sin configurar nada. OpenAI solo se usa si el panel lo
  guarda, y entonces sí hay que pegar su key.

7. REGLAS DE NEGOCIO IMPLEMENTADAS (PROMPTS)
=====================================================================
  - Dominio cerrado: solo mantenimiento y tratamiento de motos. Rechazo
    literal permitido: "Solo puedo ayudarte con mantenimiento y
    tratamiento de motocicletas."
  - Prohibido inventar cifras, torques, intervalos, presiones o
    procedimientos.
  - Si no está en el manual (modo doc): frase literal de "No encuentro esa
    información en el documento técnico cargado...".
  - Jerarquía en híbrido: REGLA CERO = el manual prevalece siempre sobre
    internet; la web solo completa lo que el manual no cubre.
  - Precios: única fuente válida es el catálogo; se respetan los valores
    de la cotización calculada; no se inventan precios ni se usan precios
    de internet. Formato exigido: "2 × Artículo = $ X COP" y "Total: ...".
  - El modelo NO escribe despedidas ni invitaciones a WhatsApp: el cierre
    lo agrega el código (appendContact) para controlar el enlace.
  - Español, tono técnico, claro y ordenado; pide aclaración si falta
    marca/modelo/componente.
  - Instrucciones de imagen: la primera frase debe describir la foto
    ("En la foto se ve…"); prohibido decir que no puede ver imágenes.

8. LIMITACIONES Y RIESGOS CONOCIDOS
=====================================================================
  L-01 (crítico) Sin backend: la API key vive en localStorage y es
       legible por cualquier script del mismo origen. Además el login del
       panel está hardcodeado (admin/123) en el HTML: cualquiera puede
       abrirlo y ver/copiar las keys guardadas de ese navegador. La key
       de pruebas de DeepSeek también está escrita en config.js, que se
       sirve como archivo público (cualquiera puede leerla).
  L-02 El documento técnico se descarga de documento_motos.txt y se
       guarda por navegador; si el sitio se abre con file:// el fetch
       falla y vuelve el aviso "no hay documento cargado". Sirviendo por
       HTTP un navegador limpio ya responde con el manual.
  L-03 Las llamadas a OpenAI/DeepSeek se hacen desde el navegador. Depende
       de CORS y del proveedor; conviene servir el sitio por HTTP y, a
       futuro, mover las llamadas a un proxy.
  L-04 La búsqueda web de respaldo (Wikipedia/DuckDuckGo) suele devolver
       poco y puede fallar por red; el sistema degrada sin avisar mucho.
  L-05 stripLinks() puede borrar texto legítimo que contenga dominios.
  L-06 El carrito del catálogo y el historial del chat se pierden al
       recargar (sin persistencia).
  L-07 Con DeepSeek, las imágenes solo funcionan con deepseek-flash
       (deepseek-v4-pro es solo texto); el chat avisa y bloquea el
       adjuntar en ese modelo.
  L-08 El selector "Fuente de respuesta" del panel solo se persiste al
       pulsar "Guardar documento"; no hay guardado independiente.
  L-09 Sin control de costo: cada mensaje híbrido hace 1 búsqueda + 1
       completion; no hay límite de uso ni conteo de tokens.
  L-10 Sin registro de conversaciones, métricas ni trazas de error.
  L-11 Contenido de ejemplo: precios, número de WhatsApp, cifras de
       marketing ("+12 años", "+3.500 motos") y ausencia de imágenes
       reales de producto.
  L-12 No hay tests ni verificación automática; todo se prueba a mano.
  L-13 El manual indica valores "orientativos" y advierte que no
       reemplaza al fabricante; el asistente puede dar un dato genérico
       si el usuario no indica modelo.
